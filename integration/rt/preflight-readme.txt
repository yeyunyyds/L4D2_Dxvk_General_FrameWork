LDB 多线程 RT：UV 修正与自发光/独立光照合并检查（v4）

这是当前游戏接口证据 + 独立静态光追测试，不是综合包 A，也不会让游戏获得光追。

操作（Windows x64）：
已运行过上一版：把本 ZIP 覆盖解压到原测试目录，保留 cache 和原先三个大依赖 ZIP，无需重新下载它们。
1. 解压本 ZIP 到独立文件夹。打开 download-dependencies.html，用浏览器下载列出的三个依赖 ZIP，放在 run-test.cmd 旁边，不要解压它们；无需安装 Python。
2. 用你现在正常可用的 LDB 启动 L4D2，进入任意地图。
3. 双击 run-test.cmd。等待独立 RT 测试窗口结束及模块检查完成，上传 results 目录中新生成的一个 rt-preflight-*.zip。

不需要 F8、F9、capture.trigger 或转头/平移。测试窗口会临时获得焦点。
独立 RT 渲染阶段最多 240 秒，包含初始化/清理的整个诊断最多 360 秒；等待游戏模块最多 180 秒。首次着色器编译可能较慢，控制台每 15 秒显示进度。
失败也上传结果 ZIP；不要只发送“成功/失败”。结果包含实际路径、模块 SHA 和候选代码。

脚本只读取正在运行的游戏；所有 runtime、缓存和日志写在本解压目录。
它不安装游戏 Hook，不更改游戏目录、CVar、注册表或驱动，不关闭游戏。
若有多个 L4D2 进程，请只保留本次测试的一个。游戏与测试脚本使用相同权限运行。

之前用户与无凭据 Windows runner 均遇到依赖下载 HTTP 404，因此本次推荐先用浏览器下载依赖。已通过 SHA 校验的依赖会缓存，下一次无需重复下载。
本版三个大依赖使用已发布的固定提交地址，并在失败时尝试 GitHub 备用入口；小型 Vulkan loader 依赖随入口包提供。
控制台会显示下载字节进度、错误、游戏 PID 和核心模块情况；详细信息保存在结果包的 progress.log、game-discovery.json 中。
缺少材料/渲染模块时仍收集现有证据，不再仅因四个模块未齐而等待 180 秒。
如果自动下载仍失败，可用浏览器打开 download-dependencies.html 中的文件页面，下载三个大依赖 ZIP 放在 run-test.cmd 旁边，不要解压，然后重跑。脚本仍会校验 SHA 和大小。
脚本和依赖版本见 preflight-manifest.json；第三方声明见 licenses 和 python/LICENSE.txt。
本版使用入口包 bin 中新编译的诊断程序，SHA 会先校验；cache/runtime 中保留的旧诊断 EXE 不会被本版运行。
游戏采集支持 shaderapivk.dll / shaderapidx9.dll，发现多个候选时记录歧义。字节模式匹配仍只是候选，不会安装 Hook。
本版修正测试三角形全零 UV：改用三个独立坐标，提交前验证行列式、有限数值与单位法线，并保存 geometry-input.json。固定 runtime 的退化 UV 分支会在回退前读取未初始化的 raw tangent；修正该输入是否消除黑屏，仍需本版实机结果确认。
一个窗口自动完成十三项：默认状态、显式不透明混合、固定曝光、提高自发光、原始/处理后材质视图、自发光视图、无效值视图、无发光材质的光源关闭/开启/物体平移/再次关闭，以及原自发光正常画面的平移对照。无需手动切换或重复运行。
每项保存间隔 16 帧的两张图；先独立读回，再核对这一项自己的物体 ID，避免旧回调当作新命中。
脚本独立解析实际 PPM 像素，要求预期三角形内部有大面积橙色、外部没有橙色污染且有明显亮度差；正常画面还必须通过物体平移对照。
近黑噪声、单个亮点、纯色清屏、灰色、未随物体移动的旧图和只有调试视图正确，都不能通过。旧版“有非黑像素”的结果不再算视觉验收。
status.json 在清理前保存一次；结果还包含拾取/读回状态、frame_trace.jsonl 就绪快照，以及发生原生异常时可取得的 crash.json / crash.dmp。
frame_trace 只覆盖 runtime 第 90 帧附近，并非全程状态；诊断渲染期间持续记录自己的进度和回调状态。
visual-acceptance.json 给出各项图像判据、正常路径的选择、平移检查和后续排查线索。调试视图用于定位，不计入验收。
summary.json 分别记录 emission_path、lighting_path。独立光照使用自发光强度 0 的材质，必须关闭时暗、开启时出现正确三角形、平移对应、再次关闭恢复暗，才算独立光照通过；它不能替代自发光通过或把总体失败改成成功。
invalid_values 是 runtime 的 NaN/Inf 调试视图：黑色表示未报告无效值，亮色表示报告无效值；该项的暗图预期与自发光视图全黑的含义不同。
正常退出与资源释放分开记录；common device objects were not disposed of 警告会保留，不会因退出码为零而宣称无泄漏。
通过仅表示独立静态 RT 场景的物体命中、可见着色和几何变化；游戏光追接入、队列、多线程与性能尚未验收。

LDB RT World Pilot v28 — 低负载GPU蒙皮Canary与完整场景稳定性

测试步骤（一次F9）
1. 解压到新文件夹，运行 run-test.cmd，按提示安装双端文件、启动游戏并进入测试地图。
2. 让人物和近处普通感染者出现在视野中，按一次F9。缓慢移动、转头，持续观察人物姿态、衣服、头发和场景。
3. 600帧诊断后自动进入60秒预览：前30秒无TAA，后30秒请求原生分辨率TAA。无需第二次按键。
   重点确认人物始终完整，画面持续更新，没有碎片化、拉伸、冻结或突然退出。
4. 控制台提示退出后正常退出游戏，保持控制台开启，等最终 ONE ZIP 路径出现，上传这一个ZIP。
不要提前退出或手动压缩尚在写入的目录。窗口化或全屏均可，测试过程中不要切换模式。

v27实机结论
- v27完整跑完600帧和60.125秒预览，三张预览均显示完整、变化中的人物姿态；没有设备丢失、冻结或非有限颜色。
- 145,761次CPU姿态模型提交全部回收，剩余Mesh、字节和待处理fence均为0，证明CPU回退是当前稳定基线。
- 60秒预览仅442帧，约7.35 FPS。Host模型准备和CPU蒙皮占主要墙钟，Host GPU 3D平均约15%、后段约23%，瓶颈在CPU供给。

v28合并验证
- v26在每帧约21次GPU蒙皮的单人物阶段连续运行60帧并留下完整第240帧；组合人物阶段突然升至约654次/帧后才碎片化并设备丢失。
- 本版每帧最多允许16次成功的持续GPU蒙皮提交，超过上限的所有人物立即沿用v27已验证的CPU姿态网格，不会形成v26的高密度突发。
- 结果为每帧记录 skinned_frame_submitted 和固定上限16。分析器要求canary确实被执行、从未超过上限、累计创建与复用严格等于提交。
- 此版用于区分“GPU蒙皮数据普遍错误”和“高密度调度/资源同步失效”，不是最终性能版本。即使稳定，16次上限带来的帧率收益也会较小。
- 感染者、衣服、原纹理、透明材质、静态世界、天空、灯光、原生无AA/TAA回读和GPU Engine采样均保留。

完整原PS/Toon/PBR、地图光源、特殊材质、全地图及长期稳定性仍未全部通过。
不改物理组件，不新增Source线程设置。restore.cmd按安装收据恢复并保留备份。

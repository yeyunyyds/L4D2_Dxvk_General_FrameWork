LDB RT Performance v38 — 完整模型回退与 Arc 生命周期复测

v37 已完整跑完 210 个 RT Present，关闭 RT 后 Mesh、Fence、纹理引用全部归零，随后 60 个普通 Present 也完成，没有设备丢失或进程异常。0/8/16 三段分别为 8.55、14.57、15.78 FPS；GPU 3D 平均约 18%、39%、43%。但 v37 为隔离显式 GPU 蒙皮而省略了 122,753 次模型部件绘制，并错误地继续给这些原始 Draw 设置 Remix Ignore，所以画面常只剩排序靠前的头部。

v38 修正显示路径：只有显式 API 实例提交成功时才屏蔽对应原 Draw；不支持或超出 0/8/16 上限的部件保留原 Draw，并启用 Remix 原生 vertex capture。这样不会恢复每帧数万个 CPU 姿态网格的创建风暴，同时让其余人物部件有一条可见回退路径。

测试步骤（一次 F9）
1. 解压到新文件夹，运行 run-performance.cmd。程序会备份并安装配套的 Client、Host 和实验 Remix 运行时，然后启动游戏。
2. 进入以往的测试地图，让一个完整人物和普通感染者保持在视野内。回到游戏后按一次 F9。
3. 保持人物可见并小幅转头。程序自动测试原生 vertex-capture 回退，以及显式上限 8、16 两档；随后关闭 RT、等待资源归零并验证 60 帧普通画面。
4. 重点观察人物是否从“只显示头”恢复为完整身体，以及有无拉伸、碎片、冻结或崩溃。不要再次按 F9。
5. 控制台要求退出时正常退出游戏，保持窗口开启，上传最终一个 rt-performance-*.zip，并描述人物完整度。

验收说明
- 设备丢失、Fence 失败、回收超时、异常退出仍直接失败。
- 两端 Bridge 明确正常清理、无异常且只保留固定运行时已有的 `[40] common device objects were not disposed of` 时显示 PASS_WITH_WARNING；该后端警告继续单列，不再与游戏崩溃混为一类。
- 本轮首先验证完整模型回退和生命周期。画面通过后，再依据原生回退/8/16 三段数据推进 GPU 与 IPC 性能。

窗口化或全屏均可，测试过程中不要切换显示模式。不改物理组件，不新增 Source 线程设置。restore.cmd 按安装收据恢复并保留备份。

LDB RT Performance v42 — 优化路径下的 GPU-64/80/96 平衡测试

v41 已完成全部 90 个 RT 帧、资源回收和 60 个普通 Present，预算遗漏为零。固定 GPU-64 的两个稳定阶段达到 7.67 和 7.72 FPS，相比 v40 的 GPU-64 参考值 4.54 FPS 提升约 70%。CPU 蒙皮每 30 帧从 2552 ms 降到约 951–961 ms；按 CPU 姿态提交数量归一化后，单部件耗时约下降 53%。

v41 的 GPU-64 稳定阶段，Arc 3D 中位占用约 37–42%，每帧仍有约 472 个模型部件走 CPU 姿态路径。v42 保留全部 CPU 优化和 3072 Mesh 条目上限，在一次测试中依次使用 GPU-64、GPU-80、GPU-96。它不会重试已知过载的 128 档，目标是找到新的最高实际帧率，而不是单纯提高 GPU 占用。

测试步骤（一次 F9）
1. 解压到新文件夹，运行 run-performance.cmd。程序会安装配套 Client、Host 和实验 Remix 运行时，然后启动游戏。
2. 进入以往的测试地图，让一个完整人物和普通感染者保持在视野内。回到游戏后按一次 F9。
3. 保持人物可见并小幅转头。程序依次运行 GPU-64、GPU-80、GPU-96，每段 30 个 RT 帧；不要再次按 F9。
4. 观察人物身体和衣服是否全部显示，有无拉伸、碎片、黑屏、长时间卡帧或崩溃。三段结束后会自动关闭 RT、回收资源并验证 60 个普通 Present。
5. 控制台要求退出时正常退出游戏，保持窗口开启，上传最终一个 rt-performance-*.zip，并描述人物完整度和大致帧率。

验收说明
- 三段都必须保留完整 CPU 姿态回退，累计计数必须闭合，预算遗漏必须为零。
- 设备丢失、Fence 失败、资源回收超时或模型重新缺失均失败。
- 主要比较三个稳定阶段的 FPS、GPU 3D、CPU 蒙皮和 Present 等待；24 FPS 暂不作为通过门槛。
- 退出时既有的 necola.dll 异常会继续单独报告，不覆盖已经完成的 RT 生命周期证据。

窗口化或全屏均可，测试过程中不要切换显示模式。不改物理组件，不新增 Source 线程设置。restore.cmd 按安装收据恢复并保留备份。

LDB RT Performance v41 — 固定 GPU-64，优化完整 CPU 姿态路径

v40 已由实机确认画面正常，但帧率没有随 GPU 蒙皮上限继续增加。三个阶段分别约为 3.25 FPS（GPU-16）、4.54 FPS（GPU-64）和 3.78 FPS（GPU-128）。GPU-128 阶段 Arc 3D 引擎中位占用约 85%，Present 阻塞明显增加，所以 64 是目前更合理的固定点。v40 同时暴露出两个剩余 CPU 热点：每 30 帧 CPU 蒙皮仍耗时约 2.05–3.16 秒，动态姿态 Mesh 的 SHA256 复用率只有约 2.1%。

v41 固定三段均为 GPU-64，直接比较优化后的预热与稳定阶段。CPU 姿态路径现在按每根骨骼只校验一次矩阵，跳过精确零权重的矩阵混合，并用帧/Draw 身份管理动态 Mesh，避免每次做两遍低收益 SHA256。Mesh 条目上限从 2048 提高到 3072，仍受相同的 512 MiB 总几何上限约束，用于消除 v40 的 5 次条目预算遗漏。所有不支持或超出 GPU-64 的部件继续走完整 CPU 回退。

测试步骤（一次 F9）
1. 解压到新文件夹，运行 run-performance.cmd。程序会安装配套 Client、Host 和实验 Remix 运行时，然后启动游戏。
2. 进入以往的测试地图，让一个完整人物和普通感染者保持在视野内。回到游戏后按一次 F9。
3. 保持人物可见并小幅转头。三段均为 GPU-64，每段 30 个 RT 帧；不要再次按 F9。
4. 重点观察人物身体和衣服是否全部显示，有无拉伸、碎片、黑屏、长时间卡帧或崩溃。三段结束后会自动关闭 RT、回收资源并验证 60 个普通 Present。
5. 控制台要求退出时正常退出游戏，保持窗口开启，上传最终一个 rt-performance-*.zip，并描述人物完整度和大致帧率。

验收说明
- 三个性能段都必须同时提交 GPU-64 内的持久 GPU 蒙皮 Mesh 和完整 CPU 姿态回退，累计计数必须闭合，预算遗漏必须为零。
- 设备丢失、Fence 失败、资源回收超时、异常退出或模型重新缺失均失败。
- 这一轮验证 CPU 优化是否高于 v40 的 GPU-64 参考值 4.54 FPS；24 FPS 暂不作为通过门槛。

窗口化或全屏均可，测试过程中不要切换显示模式。不改物理组件，不新增 Source 线程设置。restore.cmd 按安装收据恢复并保留备份。

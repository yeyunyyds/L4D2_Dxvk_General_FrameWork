LDB RT Performance v35 — Arc 固定负载稳定性

本版继续暂停五分钟 Beta。目标是先消除 B580 的 VK_ERROR_DEVICE_LOST，并测出可持续的直接光基线；人物完整度不在本轮验收范围内。

测试步骤（一次 F9）
1. 解压到新文件夹，运行 run-performance.cmd。程序会备份并安装配套的 Client、Host 和实验 Remix 运行时，然后启动游戏。
2. 进入高压测试地图，让人物和普通感染者保持在视野内。回到游戏后按一次 F9。
3. 保持同一个场景，正常小幅转头或移动；不要再次按 F9。程序先用 8 帧把 GPU 蒙皮网格上限从 4 逐步升到 32，再固定 32 测试 120 帧。
4. 控制台要求退出时正常退出游戏，保持窗口开启，上传最终一个 rt-performance-*.zip。

上次结果
- v34 完成了 16 网格的 30 帧阶段，并证明 SHA-256 复用没有混淆网格身份：16 个网格创建后复用 464 次。
- 进入 32 网格阶段后第三帧，Remix 明确报告 VK_ERROR_DEVICE_LOST。CMD 随后保存了不完整故障包并允许正常关闭；这不代表性能测试完成。
- 人物显示不全符合性能隔离策略：不支持 GPU 蒙皮和超过上限的 CPU 姿态模型会被有意省略。

v35 策略
- 光追配置在启动时固定，不在测试中途切换：TAAU、0.75 内部分辨率、直接光开启、二次反弹关闭、RTXDI 关闭、间接积分设为基础重要性采样。
- 0.75 倍宽高只追踪原生像素数的 56.25%，用来降低完整 ReSTIR GI 在 Arc 上的计算与显存瞬时压力。
- 前 8 帧依次允许 4、8、12、16、20、24、28、32 个 GPU 蒙皮网格，避免单帧突然创建 16 个新动态 BLAS。
- 预热结束后固定 32 个网格，连续记录四个 30 帧窗口。首次着色器编译和资源建立只计入预热。
- 通过标准是完整结束 128 帧、恢复成功、无设备丢失、无 CPU 姿态网格混入；四个稳定窗口仍以 24 FPS 为进入后续完整显示工作的最低目标。

窗口化或全屏均可，测试过程中不要切换显示模式。不改物理组件，不新增 Source 线程设置。restore.cmd 按安装收据恢复并保留备份。

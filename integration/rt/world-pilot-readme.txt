LDB RT World Pilot v26 — Remix 蒙皮步幅修正与完整人物复测

测试步骤（仍然一次F9）
1. 解压到新文件夹，运行 run-test.cmd，按提示安装双端文件、启动游戏并进入测试地图。
2. 让人物/近处模型出现在视野中，按一次F9。缓慢移动、转头，持续观察人物姿态、衣服、头发和场景。
3. 600帧诊断后自动进入60秒预览：前30秒无TAA，后30秒请求原生分辨率TAA。无需第二次按键。
   重点看人物是否完整、动画是否正确，有没有拉伸/爆炸/部件错位；其次看轮廓小方块、拖影和帧数变化。
4. 控制台提示退出后正常退出游戏，保持控制台开启，等最终 ONE ZIP 路径出现，上传这一个ZIP。
不要提前手动压缩尚在写入的目录。GPU计数器若不可用会记录原因，不妨碍主要采集。

v26合并内容
- 修正自定义 Remix 运行时中三权重蒙皮的顶点步幅：每顶点为3个float（12字节），不再错误地按4字节跨到下一顶点。
  v25出现的人物拉伸以及随后VK_ERROR_DEVICE_LOST与此布局错误一致；本版同时拒绝数组总数、空指针和骨索引范围异常。
- 保留Bridge的“count为标量总数”序列化修正；这与运行时的“每顶点步幅”是两个独立维度，两者现在一致。
- 在实机正确性验收期间保留完整CPU蒙皮结果边界校验，异常姿态不会送进BLAS。确认稳定后再把该校验降为抽样以减少Host开销。
- 本包必须配套下载哈希锁定的新Remix运行时；旧v25运行时不能用于本次复测。

v25继承内容
- 根据v24实机分项，持续瓶颈位于Host模型路径：CPU蒙皮约占墙钟32%至35%，模型总路径约66%至73%；
  Present约0.11ms/帧，Host GPU 3D平均仅约49%至55%。因此本版直接处理CPU供给，而不是继续调显卡选项。
- 对完整审核、无morph、三权重的VertexLitGeneric/NekoToon模型，创建一次基础网格，随后每帧只提交骨矩阵。
  基础位置、UV、权重和索引参与稳定身份；骨矩阵不进入网格键，动画姿态不再每帧创建一套新Mesh。
- 带morph、未知shader、异常骨权重/索引/矩阵以及所有其他布局继续走v24的CPU重建路径。
  这不是全模型无条件切换，回退边界保留已有显示覆盖。
- 修正固定Bridge中Remix蒙皮数组的序列化尺寸，使count遵循公共API的“标量总数”定义；
  增加持久蒙皮Mesh创建、复用和提交计数，最终ZIP可同时验收正确性、命中率、Host耗时与GPU供给。
- 保留v24的原生无AA/TAA回读、QPC分项、GPU Engine采样、shader普查、纹理证据及一次F9归档。
  两段动态画面仍不是严格同姿态A/B，需结合每帧模型调用量解释FPS，不能只比较两个屏显数字。

完整原PS/Toon/PBR、地图光源、特殊材质、全地图及长期稳定性仍未通过；客户端退出异常仍待处理。
本版优先验证持久GPU蒙皮是否保持人物正确显示并降低Host供给成本；不改物理组件，不新增Source线程设置。
restore.cmd按安装收据恢复并保留备份。

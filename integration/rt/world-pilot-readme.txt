LDB RT World Pilot v27 — GPU蒙皮隔离与完整显示稳定性复测

测试步骤（一次F9）
1. 解压到新文件夹，运行 run-test.cmd，按提示安装双端文件、启动游戏并进入测试地图。
2. 让人物和近处普通感染者出现在视野中，按一次F9。缓慢移动、转头，持续观察人物姿态、衣服、头发和场景。
3. 600帧诊断后自动进入60秒预览：前30秒无TAA，后30秒请求原生分辨率TAA。无需第二次按键。
   重点确认人物不再碎片化、拉伸或冻结，全部部件仍然显示；其次观察轮廓小方块、拖影和帧数变化。
4. 控制台提示退出后正常退出游戏，保持控制台开启，等最终 ONE ZIP 路径出现，上传这一个ZIP。
不要提前退出或手动压缩尚在写入的目录。窗口化或全屏均可，测试过程中不要切换模式。

v27修正
- v26实机确认12字节权重步长修正已加载，但人物阶段仍出现碎片化；组合人物阶段负载增大后，Remix在第244帧报告
  VK_ERROR_DEVICE_LOST。游戏进程没有退出，因此屏幕冻结、控制台等待一段时间后才报告 api_mesh_fence_failed。
- v24的CPU蒙皮路径曾完整显示人物和衣服。v25/v26共同新增的持续GPU蒙皮在两次实机中均先产生错误人物几何，随后设备丢失。
  本版默认隔离该路径，所有已支持的动画模型恢复为每姿态CPU蒙皮网格，优先恢复完整显示和稳定运行。
- GPU蒙皮实现及修正后的Remix运行时仍保留在代码和独立原生测试中，便于以后离线定位；游戏运行时不会提交蒙皮Mesh。
  最终分析器要求 skinned_submitted、skinned_created、skinned_reused 全为0，否则本次安全回退不通过。
- 感染者、衣服、原纹理、透明材质、静态世界、天空、灯光、一次F9采集、原生无AA/TAA回读和GPU Engine采样均保留。

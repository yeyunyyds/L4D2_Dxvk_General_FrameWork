LDB RT Performance v31 — GPU蒙皮压力转移基线

本版暂停五分钟Beta，只测试帧率与GPU转移边界。

测试步骤（一次F9）
1. 解压到新文件夹，运行 run-performance.cmd。程序会备份并安装配套的client与Host文件，然后启动游戏。
2. 进入高压测试地图，让人物和普通感染者保持在视野内。回到游戏后按一次F9。
3. 保持同一个场景，正常小幅转头或移动；不要再次按F9。程序自动测试四档GPU蒙皮上限：4、64、256、1024，每档60帧，共240帧。
4. 本次关闭原生TAA切换和图像回读，避免它们干扰Host供给与GPU提交测量。
5. 控制台要求退出时正常退出游戏，保持窗口开启，上传最终一个 rt-performance-*.zip。

v30实机结论
- v30在144.609秒内完成436帧，平均约3.0 FPS，随后出现D3DERR_DEVICELOST／VK_ERROR_DEVICE_LOST。
- 最初无TAA阶段的Host 3D Engine平均约18.7%；启用原生TAA后的对应3D Engine平均约78.4%，同时Present等待显著增加。因此任务管理器约20%的显示不能单独代表整个运行阶段。
- v30累计201,996次模型提交，其中GPU蒙皮2752次，只创建57个GPU蒙皮网格并复用2695次；总体却创建约171,000个以CPU姿态为键的网格。CPU蒙皮、逐姿态哈希／几何构建和CreateMesh抖动是当前主要结构性成本。

v31策略
- 四档按同一进程顺序运行，一次结果同时给出每档FPS、Host模型耗时、CPU蒙皮耗时、网格创建耗时和Present耗时。
- GPU蒙皮路径保留位置、权重、骨骼索引和骨骼矩阵有限值／范围校验，但取消对每个GPU顶点再执行一次完整CPU蒙皮的重复校验。
- 1024是实验上限，不是最终默认值。若某档崩溃，前面已完成档位仍能确定性能与稳定边界。
- 24 FPS是本阶段最低目标；采集成功不等于达到24 FPS，结果中的 performance-analysis.json 会分别报告。

本测试不是长期稳定性、最终画质或完整光追验收。窗口化或全屏均可，测试过程中不要切换显示模式。
不改物理组件，不新增Source线程设置。restore.cmd按安装收据恢复并保留备份。

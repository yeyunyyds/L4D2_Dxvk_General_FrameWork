LDB RT World Pilot v22 — 索引模型、纹理绑定复用与设备释放前回收

测试步骤（一次F9）
1. 解压到新文件夹，运行 run-test.cmd，按提示安装双端文件、启动游戏并进入测试地图。
2. 先让普通感染者出现在近处视野中，再按一次F9。可缓慢移动、转头；尽量同时看到人物、武器和静态场景。
   预览期间也可继续召唤普通感染者并观察；无需追加采集按键。
3. 原600帧诊断结束后，自动进入60秒中性材质实时预览。继续正常移动，无需第二次按键。
4. 等控制台提示预览完成、要求退出后正常退出游戏；保持控制台开启，等待最终 ONE ZIP 路径，再上传该ZIP。
请勿在60秒预览期间提前退出或手动压缩尚在写入的目录。完整结果ZIP会在退出与分析后更新。

600帧诊断：1–30原光栅；31–120世界/HUD；121–180天空；181–240 Neko贴图；
241–300组合模型贴图（含符合已审核程序/布局的感染者），头灯30；
301–360中性材质低照明3；361–420感染者亮绿不透明自发光双面对照，其他模型正常底色；421–540均恢复正常不透明底色；541–600移除API模型并检查回收。
随后自动重新开启RT，继续60秒中性材质预览（头灯30），最后按GPU完成状态回收并恢复原光栅。
预览单独记录，不继续扩张逐Draw二进制trace；包含开始、中段和结束前的三份颜色回读。

v22修正（保持一次F9）：
- 模型保留原索引、三角形顺序、UV及顶点接缝，避免每个三角形复制3个64字节顶点。
  已审核FLOAT3法线优先；其他模型采用按原顶点/接缝累加的面积加权几何法线，不宣称完整恢复原材质法线。
- 纹理通过资源私有cookie绑定持久DDS；cookie随资源销毁，避免COM地址重用串贴图。
  游戏通过Surface写入、UpdateSurface、UpdateTexture更新贴图时使旧绑定失效。
  源引用淘汰后仍能复用DDS绑定，不再因128MiB源引用预算反复回退。后台文件仍保留至退出。
- DDS证据总额仍64MiB，其中普通模型最多48MiB，剩余额度优先用于感染者依赖和派生底色。
- 逐Draw日志对重复快照和管线状态分别去重，保持全部Draw/转换/结果计数；不以抽样冒充完整日志。
- RT资源在设备释放前清理，异常采集终止也尝试完成部分帧的GPU查询后回收；退出尾部重复调用不再操作旧设备。
- 基于本次输入额外放行2套审核后的完整VS；其他未知程序和特殊混合/深度管线继续明确拒绝。
- 人物后半段不再采用合成金属、半透明、自发光材质，以免干扰衣服颜色判断。
  感染者361–420帧仍自动进行亮绿、不透明、自发光双面对照，其余阶段使用正常不透明底色/明确回退。
- 近身采样同时覆盖Infected和VertexLitGeneric，兼容感染者模型替换使用的不同shader路径。

保留的v20机制：
- Infected仅放行已审核的完整VS/PS身份及48字节声明，依据c58..60世界矩阵和c8..11相机重建。
  保留原基础UV，有效FLOAT3源法线导入；零法线按顶点回退三角面法线。其他程序/布局仍明确回退。
- 纹理活跃源缓存128MiB/256引用；导出DDS后可淘汰源引用并保留资源cookie对应的文件绑定。无剩余网格引用的闲置API材质也在完成后回收。
- 运行期DDS后台文件最多512MiB/1024份，按内容去重，保留至退出以供后台异步加载；这不是GPU显存承诺。
  诊断DDS副本另限64MiB，runtime-textures不加入ZIP。未保留副本的绑定以evidence_saved=false明确记录，不能称为已完整验证贴图文件。
- 复制源纹理已有的全部mip，不生成缺失尾级；DXT1/3/5压缩块原样保留，X8转BGRA且alpha固定255。
  单基础级最多16MiB，整链最多24MiB；每帧至多4次新读取、24MiB加文件头。额度不足时保留明确合成材质回退。
- 几何限制仍为256MiB活跃、96MiB单帧新增、1024 Draw/帧、2048 Mesh（按本次实际模型数量调整句柄上限，几何字节上限不变）、8个待完成查询；超限只遗漏相应模型并计数。

这仍是部分场景/材质的实验版，60秒预览不代表完整实时游戏、长期稳定性、性能或Source生产端并行准备验收。
原PS/Toon、完整PBR和透明材质尚未复现；感染者仅重建已审核的底色依赖。其他人物仍以原有几何法线为主。

LDB RT Performance v39 — 完整显式模型与 GPU 蒙皮卸载对照

v38 已被实机数据否决。全局 Remix vertex capture 在第一段 30 个 RT Present 中耗时 96.7 秒，仅 0.31 FPS；Present 阻塞 94.8 秒，GPU 3D 平均 86.25% 并频繁达到 100%。画面表现为黑屏和花屏粒子，音画均数秒才推进一次。日志没有设备丢失或显存不足；这是复杂 Source 顶点着色器全量捕获产生的错误几何与不可接受负载。

v39 关闭全局 vertex capture，恢复 v23 已经实机证明人物部件完整的显式 API 路径。0、8、16 只表示每帧最多多少个合格部件使用持久 GPU 蒙皮；其余已支持部件继续建立显式 CPU 姿态 Mesh，不再省略，也不依赖原生着色器捕获。三段各 30 帧，随后关闭 RT、回收资源并验证 60 个普通 Present。

测试步骤（一次 F9）
1. 解压到新文件夹，运行 run-performance.cmd。程序会安装配套 Client、Host 和实验 Remix 运行时，然后启动游戏。
2. 进入以往的测试地图，让一个完整人物和普通感染者保持在视野内。回到游戏后按一次 F9。
3. 保持人物可见并小幅转头。依次观察完整 CPU、GPU-8+CPU 回退、GPU-16+CPU 回退三段；不要再次按 F9。
4. 重点观察人物身体和衣服是否全部显示，有无拉伸、碎片、黑屏、长时间卡帧或崩溃。三段总计 90 个 RT 帧，之后会自动关闭 RT并验证普通画面。
5. 控制台要求退出时正常退出游戏，保持窗口开启，上传最终一个 rt-performance-*.zip，并描述人物完整度及大致流畅度。

验收说明
- 每个性能段都必须实际提交 CPU 姿态 Mesh；8/16 段还必须实际提交对应的持久 GPU 蒙皮 Mesh。
- 设备丢失、Fence 失败、资源回收超时、异常退出或模型重新缺失均失败。
- 本轮先恢复完整显示并比较 GPU 卸载效果。帧率数据用于选择下一轮优化入口，不作为 24 FPS 门槛。

窗口化或全屏均可，测试过程中不要切换显示模式。不改物理组件，不新增 Source 线程设置。restore.cmd 按安装收据恢复并保留备份。

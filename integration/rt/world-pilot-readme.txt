LDB RT World Pilot v24 — 原生分辨率抗锯齿对照与 GPU 供给诊断

测试步骤（仍然一次F9）
1. 解压到新文件夹，运行 run-test.cmd，按提示安装双端文件、启动游戏并进入测试地图。
2. 让人物/普通感染者出现在近处视野中，按一次F9。缓慢移动、转头，同时观察衣服、头发及场景。
3. 600帧诊断后自动进入60秒预览：前30秒保持原版无TAA，后30秒请求原生分辨率TAA。
   后半段重点看人物小方块是否减轻，以及移动时有没有拖影、透明边缘是否异常。无需第二次按键。
4. 控制台提示退出后正常退出游戏，保持控制台开启，等最终 ONE ZIP 路径出现，上传这一个ZIP。
不要提前手动压缩尚在写入的目录。GPU计数器若不可用会记录原因，不妨碍主要采集。

v24合并内容
- 保留已验证v23人物/服装/普通透明接入、4GiB运行期DDS保护与512MiB活跃几何额度。
  v24是交付版本，600帧绘制格式/覆盖语义仍为trace20、coverage23，不另做重复的覆盖阶段。
- 预览前30秒保持upscalerType=0；后30秒请求TAAU模式3，显式resolutionScale=1.0。
  不使用默认75%内部尺寸。API成功是配置请求证据，实际边缘改善/运动历史仍需画面验收。
- 两阶段各保存一份无缩放BGRA8颜色证据。单份最大16MiB，更大输出只保存中心1024×768原生像素裁剪。
  原有640×400浮点诊断与三份预览回读保留。同步回读造成的开销单列，不能当成日常游戏帧耗时。
- Host按窗口统计元数据、Draw转换、静态处理、模型捕获/CPU重建、贴图读取/写入/底色生成、
  SHA256、几何构建、API材质/Mesh/Instance、资源回收、原始模型Draw、Present与图像回读耗时。
  这些是含等待的嵌套墙钟耗时，不等于线程CPU占用或GPU渲染时间，不能把各项直接相加。
- Python后台每秒可选采样 Windows GPU Engine，绑定游戏与Host PID，各引擎分开保留。
  不能只凭任务管理器3D栏判断光追GPU负载，也不能把重叠引擎相加当总GPU百分比。
- SHA256复用不可变算法提供器，每次仍创建独立哈希对象，不复用易变模型/贴图的数据或结果。
  原始几何、UV、透明与源纹理分辨率不因此改变；实际游戏性能收益待测。
- 收集最多128类源shader计数，帮助同时判断特殊材质/效果路径；它不等于新增了对应材质支持。
  本版不把未知VS、加法、深度专用pass无条件改成不透明模型。

完整原PS/Toon/PBR、地图光源、特殊材质、全地图及长期稳定性仍未通过；客户端退出异常仍待处理。
当前动画姿态仍由CPU重建并逐姿态创建Mesh，尚未改为完整l4d2-rtx原资源或GPU蒙皮路径。
不改物理组件，不新增Source线程设置。restore.cmd按安装收据恢复并保留备份。

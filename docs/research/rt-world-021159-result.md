## Host 供给瓶颈

以 Present 计数作为窗口帧数。无抗锯齿预览为 436 帧/30.069 秒，约 14.50 FPS；TAA 预览为 347 帧/30.213 秒，约 11.49 FPS。两段画面和可见模型数不同：无抗锯齿段约 141 次模型调用/帧，TAA 段约 195 次/帧，因此不能把 FPS 差值直接归因于 TAA。

| Host 作用域 | 无 AA，占墙钟/每帧 | TAA，占墙钟/每帧 |
| --- | ---: | ---: |
| model | 66.42% / 45.81 ms | 72.51% / 63.14 ms |
| prepare | 44.86% / 30.93 ms | 49.55% / 43.15 ms |
| CPU skin | 31.83% / 21.95 ms | 34.82% / 30.32 ms |
| geometry hash | 8.29% / 5.71 ms | 9.54% / 8.30 ms |
| geometry build | 9.72% / 6.70 ms | 9.64% / 8.39 ms |
| CreateMesh | 2.74% / 1.89 ms | 2.73% / 2.38 ms |
| Present | 0.16% / 0.11 ms | 0.13% / 0.11 ms |

这些计时作用域有嵌套，百分比不能相加。纹理读取、DDS 写入和感染者底色烘焙在预览中均为 0，排除了持续磁盘 I/O；Present 也没有阻塞。主要成本是每帧在 Host CPU 重新读取模型输入、CPU 蒙皮、哈希姿态后的顶点并创建新几何。

Arc B580 的 Host 进程 3D engine 在无 AA 段平均 49.23%、中位 55.97%、峰值 71.12%；TAA 段平均 54.54%、中位 53.34%、峰值 71.65%。游戏进程没有独立 GPU engine 行，符合实际 Vulkan/RT 工作在 64 位 Host 的结构。GPU 未饱和是真实结果，不是任务管理器选错进程造成的假象。

## 边缘与下一步

运行期请求 `resolutionScale=1.0` 和 `upscalerType=3` 均返回成功，两个 1920×1200 原生回读也完整。不过动态场景不是同姿态 A/B；目视检查中，人物轮廓的小方块/光晕在 TAA 图中仍可见，尚无证据表明原生 TAA 已解决它。

下一项应把已审核、无 morph 的三骨骼模型改为持久基础网格，并通过 Remix API 的骨骼实例扩展逐帧提交骨矩阵；其余模型继续走现有 CPU 回退。它同时针对 CPU 蒙皮、逐姿态哈希、几何重建和频繁 CreateMesh，并给时域算法稳定的网格身份。固定 Bridge 的蒙皮数组序列化尺寸还需先修正和门禁验证，不能直接打开该 API。完成后沿用一次 F9，在同一包中同时检查显示完整性、持久网格命中率、Host 分项和 GPU 供给。

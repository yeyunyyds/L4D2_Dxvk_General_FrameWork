## 已经解决的输入阻断点

最终模型尝试 4,080 次，3,480 次完成重建及转换：原矩阵 60、普通三权重 2,160、Neko 三权重 1,260，即平均每帧 58 次模型 Draw。其余 600 次在 pipeline 门槛拒绝。本轮运行时没有相机精度误拒绝、非骨骼 0 权重拒绝或顶点预算拒绝的计数。

这些是路径执行证据，不是 58 个完整对象，也不是恢复率。镜头和实际模型提交与前轮不同，不能把 420→3,480 直接解释为版本带来的可见覆盖增长。

共保存 237 份主几何完整的输入、13,679,512 字节 payload。最终阶段 81 份：天空6、普通模型29、其他静态25、Neko21。该阶段记录的 Neko 候选没有配额或字节预算遗漏；普通模型另有13个输入键触及4 MiB 家族字节预算，并非 ZIP 丢文件。各阶段分别去重，跨阶段样本不能相加当作对象数。

8 份启用 morph 的输入取得了完整 POSITION1，长度、引用范围和哈希均通过。最后阶段的两份分别含 3,179/1,102 个顶点，其中 571/64 个顶点的 xyz 增量非零，最大绝对增量约 0.3111/0.00777。这证实原先仅有256字节前缀确实不足；本轮没有用零数据替代真实 morph。PS 常量已按224个float4保存。

## 原 shader 与重建数学一致，但不等于后端正确接收

137 份相关输入的生产数学 CPU 回放中，135 份成功：天空24、刚性4、普通三权重56、Neko51。另两份未知 VS 输入 `67264/67268` 的原状态均为 alpha 混合开启、深度写入关闭；实际运行时在 pipeline 阶段正确拒绝，并未误转换。

对成功的111份模型、232,671个顶点，独立解析并执行原 SM3 字节码中影响 POSITION/UV 的数据流，使用实际完整 morph、骨骼常量和声明解码，与生产重建输出比较：UV完全一致，640×400下最大投影差约0.00186像素。这个检查覆盖了实际非零 morph，而不仅是新的手写公式互相比较。

再用最终阶段21份 Neko 重建世界位置、真实 IB/base 参数及相机投影三角形，得到连贯的人物轮廓，与原光栅前景位置相符；实际最终 GBuffer 只有局部新增三角形。这将后续排查重点转向实际上传/绑定的 VB/IB、状态继承以及 Remix 的实例/几何/材质处理。

该三角形投影是诊断图，不是 GPU 渲染。输入采样发生在最终阶段开始附近，GBuffer 在240读取，人物动画可能变化；不包含纹理裁切和完整遮挡，不能据此逐像素归因或给出人物恢复百分比。它也不能单独证明实际 GPU 收到的字节已经与 CPU 输出相同。

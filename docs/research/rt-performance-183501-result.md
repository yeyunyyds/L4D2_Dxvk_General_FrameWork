# RT Performance v34 183501 结果与 v35 Arc 稳定基线

本次回包没有完成性能协议。它完成了 16 个 GPU 蒙皮网格的首个 30 帧窗口；进入 32 网格阶段后只运行 3 帧，Remix 随即报告 `VK_ERROR_DEVICE_LOST`。采集器在故障后生成不完整结果包并允许用户正常关闭，因此 CMD 显示结束只代表证据已保存。

16 网格阶段提交 480 次蒙皮，创建 16 个姿态网格并复用 464 次。同帧唯一网格数等于提交数，说明 v33 姿态槽隔离和 v34 精确 SHA-256 身份复用没有混淆角色。进入下一阶段后又创建了预期的 16 个网格；设备在第三帧的 fence 同步处丢失。日志同时记录 `DxvkSubmissionQueue: Failed to sync fence: VK_ERROR_DEVICE_LOST`、`waitForIdle: Operation failed` 和 `Command submission failed`。

画面中的人物缺部件不能用于判断材质回归。性能模式有意不提交不支持 GPU 蒙皮、包含其他形变以及超过当前上限的 CPU 姿态网格。本次共省略 21,037 次候选提交，人物不完整符合隔离协议。

v34 在原生 1920×1200、无升频、RTXDI 与二次反弹默认开启的路径运行；Arc 不支持 NRC 后，Remix 实际启用了 ReSTIR GI。该配置把动态 BLAS 扩容与完整间接光压力叠在同一次突增上，无法区分是哪一项触发设备丢失。16 网格窗口的 8.70 FPS 还包含 1308 ms 的首次 Present 编译阻塞，因此不是可持续帧率。

v35 固定为 Arc 直接光稳定性配置：TAAU 0.75、直接光开启、二次反弹关闭、RTXDI 关闭、间接模式设为基础重要性采样。前 8 帧按 4、8、12、16、20、24、28、32 逐步建立姿态网格，随后固定 32 连续测四个 30 帧窗口。首次编译与资源建立只进入预热窗口。一次 F9 同时验收设备稳定性、固定负载帧率和 GPU 3D Engine 数据，仍不验收人物完整度。

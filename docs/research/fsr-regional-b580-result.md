# 区域保护版 B580 实机分析

结论：区域保护减少了整帧拒绝，也采到了真正通过质量检查并成功调用生成帧 Present 的输出；但画面仍有明显变形，尚未达到“插帧正确”的目标。

本次 Host／Client 日志的开发标识均为 `ldb-capture-dev+be7d88f56bcbd42b`，与本轮发布包匹配。设备为 Arc B580，驱动 `101.8531.0`，1920×1200。上传没有五个二进制的哈希清单，所以不扩展为所有安装文件都已逐个校验。会话约 146.66 秒，包含进图前的主菜单时间。

1534 次生成帧调用均成功，其中 1370 帧仍有局部细特效风险标记。这证明新路径在有风险时能够继续生成，同时没有直接关闭原风险检测。Bridge Client 与 Host 均正常退出，日志没有设备丢失错误。前次偶发启动闪退仍没有确定原因。

本次全程为 `generated` 生成帧预览，未切换双呈现，因此后端调用数仍为 5858，不能解读为已验证帧数翻倍或显示节奏。旧会话 4.97% 与本次 81.47% 的接受率来自不同动作、场景和时长，也不是受控性能比较。

## 画面检查

16 组截图中，13 组的 `quality_accepted=true`，与同帧 `generated_present.hresult=0` 及最终 metrics 对应；3 组被无效场景覆盖检查拒绝。本次已经能检查成功调用 Present 的候选，而非只有被拒绝的诊断图。

获准样本的黄色保护区共有 836457 个保存位置，均与当前原帧像素一致。截图是 640×400 的抽样，不把这个结果扩大为每个原生分辨率像素都已校验。

可见缺陷包括：

- 第 4435 帧：建筑边缘和细节错位、拼接，属于被接受的输出。静态几何也出现问题，应优先核验深度、矩阵时序及运动输入。
- 第 5461、5464 帧：白色人物轮廓破碎、拖影，下方机枪出现涂抹／透叠状残影。原帧人物本身已是白色，新增缺陷是轮廓被打散和位移，并非把原有白色材质都归因于插帧。
- 同两帧 `near_draws=0`、`near_colour_mask_valid=false`，机枪没有落入近景保护分类。现有记录不能判断它是漏识别的视模，还是安装式／世界几何武器；需要区分后处理。
- 第 4000、4002、4987 帧未见同等程度的大范围变形，但缺少独立中间帧真值，不能因此认定完全正确。4987～4990 帧前景覆盖约 60.7%，有较大区域直接保留原帧。

## 下一步优先级

先核对 SDK 输入的深度、当前／前帧矩阵配对、运动矢量方向与尺度，并同时检查未做保护的 SDK 输出，区分输入、官方插帧与本项目后处理产生的错误。然后针对机枪／人物改善运动与保护分类。应继续把这一组信息合并采集，避免依靠生成成功率判断正确性。

当前不用为了增加截图数量马上重测。已有数据已经足够确认主要缺陷，后续数值归因若需要新包，应一次保存同帧的 SDK 输入、原始 SDK 输出和最终合成结果。

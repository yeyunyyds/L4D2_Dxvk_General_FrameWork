## 原始场景输出与离线解码

已逐像素验证 30/120/240 的上传颜色 PNG 与各自原始 RGBA32F 按既定显示规则生成的 RGB 完全一致。控制段可见游戏地图、武器及 HUD；120/240 颜色图可见贴图地面、建筑和物体，但亮度低，武器、HUD 等未合成内容缺失。不能把控制段的完整光栅画面算成完整 RT 画面。

控制段 depth 全零、normal 为固定 `(0,0,0,1)` 原始 uint32。开启 RT 后：

| 采样 | 投影深度范围 | `0 < depth < 1` 像素比例 | 法线原始编码种类 |
| --- | --- | ---: | ---: |
| 120 | 0.9164235～1.0 | 83.5578% | 599 |
| 240 | 0.9207562～1.0 | 80.0488% | 482 |

固定运行时的 `rtx_globals.h` 将 ray miss 深度设为 1.0；`geometry_resolver.slangh` 写入的是投影位置 `z/w`。这些是缩放采样下的投影深度分布，不能称作线性距离，也不能把比例当作全地图几何覆盖率。

此次沿实际 primary GBuffer 的读写路径核对了法线编码：`gbuffer_helpers.slangh` 使用 `float2x32ToSnorm2x16` / `snorm2x16ToFloat2x32` 及八面体映射，`packing_helpers.h` 的 16 位量化采用无符号偏置表示，分母是 **65,534**。它不同于标准二补码 SNORM，也不能直接套用辅助 `cpu_gpu_compat.h` 的 UNORM 65,535 公式。

对每个 16 位分量先算 `x = code / 65534 * 2 - 1`，再执行固定源码的 signed-octahedral unfolding 和归一化；例如 `0x7fff7fff` 解为地面的 `(0,0,1)`。原始 R32_UINT 编码被保存在 RGBA32F 文件的第一个 uint32 字中，G/B 为零、alpha 为整数位模式 1。把整数编码按 float 显示会产生 NaN 图样；本次离线解码未发现超出合法量化范围的半字，解出的地面 +Z、墙面和物体方向与投影深度轮廓、颜色场景相符。这些派生预览与原上传文件分开保存，没有修改原始图像。

这组“控制段清零 → RT 段出现随视角变化且与场景相符的几何字段”，结合固定源码中对应的 Ray Query GBuffer 写入路径，支持本轮受限世界 RT 输出链路通过。未采 GPU dispatch 计数器，未验收每种材质、阴影、反射或间接光的精确正确性。

## 稳定性与仍需保留的边界

本轮最久 Present 记录间隔为第 33 次附近约 **1,370.07 ms**，随后持续完成采集。没有再次出现上轮提交中止，但这次最长停顿低于旧的 2 秒生产端等待，所以不能仅凭本轮结果将先前根因完全坐实，也不能把初始化变快归功于延长等待；shader 缓存等因素未隔离。v4 已有独立生产队列用例验证超过 2 秒的延迟恢复，本轮无需为了单独复验超时而再采一组数据。

逐 Draw 内存读取、getter、记录和同步读回仍在运行，记录时长不用于生产帧率验收。Client 绘制线程 21144、Host 消费线程 13972 的串行 RPC 记录不证明 Source producer 准备任务的并行程度。SDK CVar 候选也不等于实际队列执行证据。接入没有新增强制 Source 单线程的设置，但多线程保留目标尚未完成实测验收。

Remix 退出仍记录 40 个 common device objects 未释放，保留为生命周期待处理项；本轮 Bridge 正常退出不等于所有资源所有权已经验收。

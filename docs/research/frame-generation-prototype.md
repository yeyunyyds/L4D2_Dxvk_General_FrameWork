# LDB v1.3.1：可显示生成帧的相机插帧原型

这一包合并了全尺寸 GPU 历史、场景/武器/UI 阶段处理、中间帧计算和真实 Present 接入。不是上一版只输出重投影图片的诊断。它保存真实渲染帧的完整颜色和场景深度，在两帧之间建立相机姿态，在 GPU 上合成中间视角，再写入 DXVK 的真实背缓冲。

## 本轮先验收画面正确性

上一轮 B580 上，运动匹配与上一帧遮挡补充均已触发，武器内部抽查的 37,888 个像素保持原样。但第 6504 帧的角色圆环特效出现局部姿态拼接，全屏无效区域比例仅 10.38%，未被原先 15% 的面积检查拒绝。完整插帧仍未验收。

本包增加局部细线特效风险检查：寻找局部平坦场景深度上的细窄中性高亮结构，当它与上一帧、计算候选均有明显颜色差异时，标记风险。任一风险标记会在 Present 前恢复**整张当前原图**，跳过生成 Present；保持原先的面积检查。此包采用保守回退来避免拼接，并没有完成圆环特效的运动重建。

这是根据颜色、形状和深度特征进行的检查，不能确定引擎材质或透明图层。亮色标线也可能触发，生成帧比例可能降低；较暗、彩色或深度复杂的特效仍不保证被覆盖。目标先是避免明显错误画面，不是帧率收益。

继续保留受限双向纹理匹配、上一帧深度遮挡补充、近景颜色主导的武器掩码和 UI 保留。运动搜索每轴最多 8 个全尺寸像素，快速运动、重复/无纹理、形变和透明效果的完整插值仍未验收。

启动脚本保持 **generated 生成帧预览**，提交间隔预算 0。一次游戏里重点观察之前出现问题的角色圆环/细线效果，同时转头、平移、射击、换弹，检查武器和 UI；可用 F8 对照原图。退出后上传一个完整 fg-results。不需要 capture.trigger，也无需单独重做多轮采集。

## 已集成的取证与原型功能

生成计算与背缓冲写入在普通帧合为一次 Vulkan 提交，减少一次同步等待。设备时间戳记录 GPU 合成耗时，逐帧统计全部 FG fence 等待、提交数、Host Present 工作、原帧/生成帧 Present 耗时及实验性间隔。

提交间隔参数可选使用 2 ms 预算；本轮脚本设为 0；驱动 Present 或图像恢复已经耗尽预算时不会额外等待。预算依据源帧到达间隔，扣除自身上一帧等待，避免估计反馈。使用 Windows 高精度等待计时器，不支持时跳过并记录；操作系统调度可能使实际等待超过预算，日志会记录实际值。这是受限的提交间隔实验，仍有同步等待，尚未实现异步调度或显示器感知的生产帧节奏，可能降低源帧率或增加延迟。`LDB_FG_PACING_MS=0` 可以关闭；允许 0–8。

可靠的双向纹理匹配会生成动态物体中间位置，掩码为蓝色；匹配不可靠且动态颜色/邻域不一致时保留当前屏幕像素，掩码为紫色；武器/UI 保留边缘扩展一个像素。用于减少相机矢量错误拖动动态物体，受限匹配不覆盖全部物体、快速运动、形变或透明效果；回退区域保持真实帧更新频率。

## 一次集中测试

1. 完全退出游戏、Host 和 Steam。备份原三个桥文件，按原位置同批替换 `bin/dxvk_d3d9.dll`、`bin/.l4d2bridge/L4D2Bridge64.exe` 和 `L4D2Bridge32.exe`。使用 x64 Host，沿用原 DXVK 2.6.1、配置和地图。此包是基于官方 v1.3.1 源码编译的实验版本。
2. 将 ZIP 解压到可写目录，运行根目录的 `start_fg_test.cmd`。它设置环境并直接启动 Steam/L4D2；如果 Steam 仍在运行，会提示先退出。无需 capture.trigger，也无需重做三轮采集。
3. 进地图后正常玩，缓慢转头、平移、观察武器和 HUD，并开关菜单。**F8** 启停插帧；**F9** 在双 Present 与“仅显示生成帧”预览间切换。预览能直接看中间帧的内容，恢复双 Present 再比较。本轮脚本开启自动取证：场景初始化和 F8/F9 切换后约等待 2 秒，每次保存 4 张连续图片；随后约每 20 秒再保存一组，全进程最多 32 张。采集只在成功生成帧时发生，无需手动触发。
4. 同一场游戏中找有感染者/队友的区域，射击并观察粒子、人物边缘；重点检查转头时武器/手部、换弹、射击和 HUD，可用 F8 对照原图；本轮不要求耗时基准。可在同一次游戏中切屏/改变分辨率检查恢复。结束后上传解压目录下完整 `fg-results` 文件夹，遇到启动/显示错误同时带上 Bridge/DXVK 日志。

F8/F9 仅在游戏窗口取得焦点时响应。如果按键未响应，可通过下方变量选择模式后完全退出再启动。菜单、加载画面、尚未取得场景矩阵、相机突变或不支持的 Present 会直接使用原帧。

## 输出与实际行为

- `frame_metrics.local_effect_risk` 和 `frame_rejected.reason=unsafe_thin_effect` 表示局部风险触发整帧恢复原图。掩码中的粉色（255,128,255）标出风险源像素；保存的候选仍可能包含错误，它不会被提交显示。
- `frame_metrics.motion_interpolated_pixels` 记录通过双向纹理匹配的蓝色像素；有计数不代表全体动态物体插值正确。
- `frame_metrics.near_colour_pixels`、`near_depth_pixels`、`ui_pixels` 记录各来源的原始覆盖；各来源可重叠，不能相加当作保留区。`foreground_pixels` 是实际保留区（含扩边）；`scene_reprojected_pixels` 记录底层映射/匹配的场景像素（局部粉色标记不改写此计数，是否提交仍看生成与拒绝事件）。`foreground_ratio` 与 `scene_reprojection_ratio` 用于识别退化候选。
- `frame_rejected` 记录候选被拒绝并恢复原图；`frame_metrics.quality_rejected` 和 `invalid_scene_ratio` 记录比例。保存的 `*-generated.ppm` 是计算候选，**不一定提交显示**；同帧存在 `frame_rejected` 时，实际提交的是 `*-current.ppm` 对应的原图。
- `frame_metrics.near_colour_mask_valid` 表示近景颜色阶段前后均完整取得；该标志验证采集条件，实际武器覆盖还要检查图像中的黄色区域。
- `fg-events.jsonl` 记录 GPU 初始化、场景/近景/UI 边界、历史失效、生成 Present、原游戏 Present、错误和总数。
- `*-generated.ppm`、`*-current.ppm`、`*-previous.ppm` 是少量检查图片；保存时降采样，**实际历史和合成是全尺寸**。`*-mask.ppm`：绿=两帧匹配并混合，青=使用当前帧重投影，白=天空旋转，黄=保留当前武器/UI，红=当前画面回退，紫=未可靠匹配的动态/颜色变化回退，蓝=双向运动匹配，橙=上一帧可见表面的遮挡补充。边缘遮挡会产生当前帧回退区域，不输出黑洞。
- 默认 `paired` 会先提交中间帧，再恢复并提交原真实帧。桥协议、游戏模拟帧和原来的响应/信号量仍按一个游戏帧处理。
- `generated` 预览每游戏帧只提交一次，显示中间帧；它用于直接验收生成内容，**不是帧率翻倍模式**。
- Reset、目标/格式/尺寸变化、失败 Present、缺失场景和 F8 切换会使历史失效或预热。开启失败时记录 `fg_error`，停止进一步生成并沿用原帧。

历史使用自身的 Vulkan 图像，不长期持有游戏表面的 COM 引用，不改变 D3D 绘制状态。生成计算没有 CPU 像素回读/上传；只有少量图片取证会回读。当前实现仍用 GPU fence 同步等待，并额外调用 Present，尚未完成生产帧节奏/异步调度。因此 Present 次数增加不能直接当作实际显示帧率或性能提升，垂直同步和驱动也可能影响交付。

## 分层范围

场景通过同目标 cViewProj、全尺寸 HDR 与深度写入识别；武器依据近景绘制前后 HDR 颜色差异建立保留掩码，完整颜色有效时不叠加原始近景深度范围；UI 依据背缓冲上的屏幕 alpha 绘制边界及绘制前后差异保留。生成帧中的武器/UI使用当前真实帧像素，避免相机重投影把它们拖动。

这是阶段和掩码处理，**不是引擎提供的三张独立透明 RGBA 图层**。UI 边界可能包含后处理，透明边缘、动态角色、粒子和光照变化仍可能有接缝或拖影。当前运动估计仅限受限双向小块匹配，没有引擎骨骼/物体运动矢量；匹配不可靠时使用保守回退，这些限制不应被理解为已验证完整动态场景插帧。

## 手动启动（可选）

必须从同一 CMD 启动已经完全退出的 Steam：

```bat
set LDB_FG_ENABLE=1
set LDB_FG_MODE=generated
set LDB_FG_LOG_DIR=D:\LDB-FG-results
set LDB_FG_CAPTURE_FRAMES=4
set LDB_FG_HOTKEYS=1
set LDB_CAPTURE_DIR=
set LDB_CAPTURE_TRIGGER=
set LDB_GPU_REPROJECT=0
start "" "C:\Program Files (x86)\Steam\steam.exe" -applaunch 550
```

本轮 `frame_metrics` 也记录 F8 关闭期间的数据，日志最多 64 MiB。图片采集会造成停顿，分析器会剔除这些帧及受影响的下一帧到达间隔。可运行：

```bat
python scripts\analyze_fg_results.py fg-results --output fg-analysis.json
```

`LDB_FG_AUTO_CAPTURE=1` 开启延迟和定时取证，`LDB_FG_CAPTURE_FRAMES=4` 是每组图片数量；设为 0 不回读图片。自动取证关闭时保留旧版有界取证行为。脚本默认自动取证开启、生成帧预览、提交间隔预算 0 ms；手动启动需额外设置 LDB_FG_AUTO_CAPTURE=1 和 LDB_FG_PACING_MS=0。直接上传整个 fg-results 即可，分析脚本不是必需步骤。

`LDB_FG_ENABLE=0` 完全关闭新路径；`LDB_FG_MODE=generated` 直接进入生成帧预览；`LDB_FG_CAPTURE_FRAMES=0` 关闭图片回读，仅留日志。

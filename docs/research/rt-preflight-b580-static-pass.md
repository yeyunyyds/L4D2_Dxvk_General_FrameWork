# B580 独立静态 RT 视觉验收通过

结果包：`rt-preflight-20261015-222206-695a12d1.zip`。对应已发布 v6 代码 `58c732be9396aec53f2e0516d8d43ba00750747c`，诊断 EXE 和固定 runtime DLL 的 manifest 与发布验证一致。ZIP CRC 完整，60 个文件，无遗漏。全部 26 张原始 PPM 已在云端独立重新计算，逐字段与包内报告一致，并人工查看正常画面、平移、材质、自发光及灯光开关图像。

**通过范围是 B580 上的独立最小 RT 场景。** 它还没有渲染 L4D2 世界，没有安装 Source 队列 Hook，也不证明游戏多线程或性能通过。原始 summary 的 `b580_rt=pending_adapter_and_image_review` 是脚本留给人工审查的状态；本次复核确认实际设备为 Intel Arc B580（8086:e20b），结合原始图像，将独立静态视觉结论记为通过。原始上传文件不作修改。

runtime 实际日志中的 GBuffer、直接光和间接光均使用 Ray Query (CS)，间接光选择 ReSTIR GI。日志中的 NVIDIA 专属功能初始化失败不改变本次已观察到的最小 RT 图像结果，也不能据此声称这些功能在 B580 可用。

v5 的两次图像已恢复可见主体，但默认后处理让轮廓外出现橙色光晕。v6 显式关闭后处理后，外部橙色覆盖率降到 0%，两条平移路径均达到 100%，支持此前“诊断配置与严格轮廓判据不匹配”的判断。没有调整像素门槛换取通过；多个后处理开关一起关闭，未分别测量每个开关对图像的贡献。

## 保留事项和下一步

资源释放仍有同一条 `[40] common device objects were not disposed of.`，分别写入两个日志。正常退出不等于没有泄漏；资源释放需要继续调查，并在后续生命周期验证中复测。本次约 35.69 秒包含初始化、截图读回和同步，不作为游戏 FPS、RT 预算或稳定 60 帧的性能证据。

游戏只读采集取得稳定的 shaderapivk.dll 选择和 189 个模块，四个目标模块无读取错误；7 个 Hook 模式和 3 个私有全局模式均为唯一候选。模式唯一不等于 ABI 或语义已验证，不能直接调用猜测的 GetCallQueue 槽位。

独立三角形视觉前置项到此完成，无需再重复同类采集。后续研发重点转为确认当前游戏队列 ABI，在对应 material context 中有序传递帧/主视图/Draw 身份，再接静态世界的相机、几何与材质。保留 Source 多线程，不设置强制单线程配置。后续用户侧观察、顺序校验和静态世界 RT 按综合包 A 合并为一个入口、一个结果 ZIP。

这只完成 G2 中“B580 实际执行所选 runtime 的最小 RT”部分；G1 的真实游戏有序接入和 G2 的 queued 世界对应仍未完成。详细机器记录见 [本次实测审查](../../research/rt-preflight-222206-review.json)，构建/交付记录见 [v6 发布验证](../../research/rt-preflight-v6-validation.json)。

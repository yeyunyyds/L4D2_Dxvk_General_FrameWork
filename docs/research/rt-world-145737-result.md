## 提交字节和原 shader 已核验到哪一层

实际取图 Present 对应的59份模型提交样本均记录上传只读核验、绑定核验和独立 VB/IB 提交通过。其中33份保存完整配对 payload，普通13、Neko7、合并13，共4,182,512字节；另26份明确触及有界预算，并非 ZIP 丢文件。

86份模型状态样本查询成功；保存的自定义 Remix 元数据字段均为0，没有发现非零自发光修饰值或 stencil/深度偏移足以直接解释本轮异常。保存的状态数组没有数值型 CLIPPLANEENABLE；转换门槛实际检查零裁剪面，不能把它写成完整裁剪面数值审计。

这些证据显著缩小了范围，但还不是 GPU BLAS/TLAS 的内容证明。300的完整配对只覆盖7个模型部件，其余部件不能由这33份数据全部排除。较早采集的21份 Neko 输入、74,742个顶点投影为连贯人物，没有左侧长条；其姿态早于300，且软件投影忽略透明裁切、剔除和完整遮挡，只能作为补充诊断，不能替代同一帧完整 GPU 几何验证。

## 下一步优先级

灯光和曝光在这些阶段没有切换，新增普通模型后反而恢复背景与人物。因此优先核查固定 Remix 后端的几何缓存、实例复用，以及 Neko 材质/诊断灯和历史状态的相互影响。源码中的 `rtx.enablePreservePath` 默认为 true，会复用未变化 Draw 的翻译结果；几何缓存也按拓扑和位置/骨骼/材质匹配复用。这些是可验证的候选路径，当前记录没有指出一个已经确认错误的缓存条目，不能直接宣布根因。

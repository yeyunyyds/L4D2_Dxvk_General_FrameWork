# 地图加载诊断

本包只增加启动脚本，不替换 DLL、Host 或配置。

1. 解压到游戏根目录，与 `left4dead2.exe` 放在一起。完全退出 Steam、游戏和 Host。
2. 运行 `start_fg_diagnostic.cmd`，尝试进入地图一次。失败后退出，压缩游戏根目录下完整 `fg-results` 上传。它将 Bridge、DXVK、FG 日志和五个已安装二进制的 SHA-256 放进同一次运行目录。
3. 如果方便做对照，完全退出 Steam、游戏和 Host，再运行 `start_fg_control.cmd` 尝试同一张地图。此对照使用当前安装的同一个 DXVK，但关闭 FG 和新增 FSR 设备能力；不替换文件。两次结果仍在同一个 `fg-results` 中。仅切换 F8 不能撤回创建逻辑设备时已启用的能力，所以这个对照需要重新启动进程。

不需要进入地图后游玩一分钟，也不需要 `capture.trigger`。若游戏弹出报错，请同时保留报错文字；若卡住，可关闭进程后上传已经生成的日志。诊断目录使用随机后缀，保留此前运行。

现有两次 FG 日志共 8979 次逻辑呈现，没有场景识别、GPU 初始化、FSR dispatch 或 FG error。这表明日志尚未覆盖到实际场景插帧，不能据此确定地图加载失败的根因，也不能排除配套 DXVK／设备能力初始化或桥的加载问题。需要 Bridge 与 DXVK 日志继续定位。

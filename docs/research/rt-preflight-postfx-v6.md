# 固定独立 RT 验收的后处理配置 v6

后续结果：[v6 已通过 B580 独立静态 RT 视觉验收](rt-preflight-b580-static-pass.md)。以下保留 v5 两次失败及 v6 修正的诊断过程。

用户的两份 v5 结果 `210725-920270cd`、`211018-d855ecdb` 均为已发布代码 `85df7f8`，小型 EXE、固定 runtime DLL 与 manifest 一致。两次各完成 13 项、1088 帧、26 次读回，耗时 35.63 / 35.34 秒；全部物体拾取成功，窗口销毁与 Shutdown 返回，没有原生异常或 minidump。实际 RT 设备均为 Intel Arc B580（8086:e20b）。两次独立 RT 进程针对同一个正在运行的游戏进程，不能据此声称游戏重启稳定性通过。原来的 40 个 common device objects 释放警告仍存在；同一条消息分别进入两个日志，不能累加为 80 个对象。

## 两次画面已经确认的变化

v4 全黑的处理后材质和自发光调试图，现已分别显示正确三角形，中心 RGB 为 (204,51,13) 和 (255,96,24)。默认最终画面的中心为 (255,198,33)。无自发光材质在独立方向光关闭时全黑，开启后可见，再次关闭又全黑；两张采样均一致。默认最终画面和独立灯光画面中的三角形也确实向右平移。NaN/Inf 视图仍全零，表示该视图未报告无效值。

这证明 alpha 初始化修正后，B580 的材质、自发光和独立灯光已产生可见输出。游戏侧两次均取得稳定的 shaderapivk.dll 模块快照，各 185 个模块；仍只是候选绑定证据，没有安装 Source Hook 或执行游戏 RT 队列。

## 为什么报告仍是失败

两次官方 v5 像素结果均已在云端独立重新计算，逐字段一致，总体仍为失败。三角形内部的橙色覆盖率都是 100%，但默认最终画面外部有 18.83% 的像素满足橙色条件，独立灯光画面为 35.92%～36.49%，超过 5% 上限。光晕也覆盖了移动前后应该清空的区域，使旧位置消失率/新位置出现率检查失败。

固定 runtime 的 [Bloom 默认开启](https://github.com/xoxor4d/dxvk-remix/blob/b73eb23053aa50d3787b0c6c8b4b8ae49962880e/src/dxvk/rtx_render/rtx_bloom.h#L81)，[postfx、运动模糊、色差和暗角默认开启](https://github.com/xoxor4d/dxvk-remix/blob/b73eb23053aa50d3787b0c6c8b4b8ae49962880e/src/dxvk/rtx_render/rtx_postFx.h#L78)，v5 没有关闭它们。截图显示明显光晕，符合默认后处理扩散颜色的行为。尚未执行关闭后的 GPU 对照，不能声称全部画面异常已被唯一归因或修复。

补充敏感性分析遍历红色门槛 32/64/96/128/192/224，结果保存于 [两次审查记录](../../research/rt-preflight-v5-two-runs-review.json)。门槛达到 96 后，两条路径的高亮主体在旧位置消失和新位置出现的检查均为 100%。这支持主体确实移动、低亮光晕污染了原检查的判断；它不改变原始失败结论，不用调高门槛换取验收通过。

## v6 的改动与范围

独立诊断每项显式关闭 Bloom、postfx 及其运动模糊、色差、暗角开关。每次实际 API 请求保存 case、选项、请求值和返回码；矩阵版本 4 额外要求 13×5 项记录完整、无重复、值为 False、API 成功。该记录证明请求成功；原始 PPM 的严格轮廓、背景、两次采样和几何平移检查仍是最终判据，所有原像素阈值保持不变。固定材质 alpha、关灯自动补光禁用及独立灯光验收继续保留。

Windows native helper 直接调用生产 configure，检查禁用选项确实传到 API，并验证任一关闭请求失败会中止该项。CPU/原生测试与包内 DLL 加载不替代新一轮 B580 画面实测。

操作仍为覆盖原测试目录、保留 cache 与三个大依赖，用 LDB 1.3.2 进图后运行一次 run-test.cmd，上传一个新 ZIP。游戏 RT 接入、Source 多线程、资源释放和性能仍待各自验收。

发布代码 `58c732b` 已通过本地 RT 回归 56 项（54 通过、2 项要求 Windows）及两个 x64 Werror 交叉编译。Windows 原生协调器 28/28，游戏采集器 16 项中 15 通过、1 项 Linux 专用跳过；生产配置请求/失败中止、固定着色器 alpha 分支、窗口/DLL 生命周期和包内 DLL 加载均通过。已取回实际发布包校验 CRC、x64 EXE、源 SHA、四个脚本与 README 字节一致，并确认三个大依赖完全复用。[详细发布验证](../../research/rt-preflight-v6-validation.json)。

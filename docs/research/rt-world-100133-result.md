## 本次实际通过的部分

独立重析二进制得到 240 次 Present、97,190 次 Draw，全部快照 valid，未发现未关联 Draw、Reset、绘制失败、viewport 不一致或管线 getter 失败。F9 前台 PID 与游戏 PID 一致，client 明确记录 capture_started/capture_stopped；模块快照完整，前后模块身份稳定。30/120/240 的颜色读回都有游戏内容，人工查看最后一张可见地图、武器和 HUD，画面没有保持全黑。不能据此将未采到的启动菜单截图也判为视觉通过。

同一段 Draw 由 client 线程 4464 发出，Host 消费线程 20624 执行；这些线程 ID 不说明 Source producer 的准备任务是否并行。SDK 布局候选读到 `mat_queue_mode=-1`，尚未验证当前 ABI 和真实任务执行；Source 队列、准备线程并行及性能仍未验收。

## 为什么没有光追画面

9,525 次 Draw 位于前 30 Present 控制段；其后 87,665 次全部在材质条件处被拒绝，实际转换为零。运行时没有 raytracing_requested_on，整个采集保持光栅。深度三个采样均为全零；法线原始 uint32 均为 `(0,0,0,1)`，最后一个字节模式按 float 解释为约 `1.4013e-45`。不能因为 alpha 非零就当成有正常的场景法线。完整采集成功与 RT 未开始是两个独立结论，summary 的 incomplete 指后者未通过。

416 个已记录材质中有 62 个 `0x480003` 格式候选，全部使用同一个已读取到的 `A1 E4 C1 1D 52 C3` shader getter。它的语义是 `mov eax,[0x521dc1e4]; ret`，从全局槽读取字符串指针。v2 只识别直接字符串地址或对象内小偏移，所以这些候选只有 FormatRead 标志，名称始终为空；唯一解出的名称是 19 个自定义材质使用的 NekoToon，保持在世界白名单之外。

不能把记录中的绝对地址硬编码成补丁：shader DLL 存在 ASLR，名称槽应从当前 getter 的有界指令中读取。当前 ZIP 没有该全局槽的数据，尚不能确认其实际字符串就是 LightmappedGeneric。独立计数有 7,880 次世界格式 Draw，其中 7,355 次通过除名称外的高层矩阵/目标/管线条件，后控制段为 6,884 次；这只是名称未知时的候选数量，不能当成已通过完整布局/来源验证或实际转换数。

## v3 修正

新增精确 A1/ret 叶函数的只读解码：验证可执行 image 中的 getter、读取有界全局指针及最多 63 字节名称、复读代码/名称/全局槽/对象身份，任一变化即拒绝。记录名称槽与实际字符串地址，不执行私有函数，不扩大世界 shader 白名单。回归覆盖有效名称、全局指针变化、空名称、32 位地址溢出和自定义 shader 的拒绝。

同时将原始 uint32/RGB 与 alpha 分开统计。固定运行时的 primary normal 源为 `VK_FORMAT_R32_UINT`（`rtx_resources.cpp`），采用打包编码（`utility/cpu_gpu_compat.h`）；不能把旧 PNG 的 float RGB 映射解释为已解码向量。原始字节全部保留，因此后续有实际 RT 数据时可离线复核传输和解码，无需单独再采一组法线。

本次正常执行 Host 清理，未找到 Bridge 异常报告；Remix 仍记录 39 个 common objects 未释放。这保留为生命周期未通过项，不影响本次材质条件阻塞的归因，也不能宣称资源释放验收完成。

测试流程保持一个入口、一次 F9、一个 ZIP。启动光栅保护、30 Present 控制段、所有状态恢复与采集结束关闭逻辑保持启用。v3 的最终构建和交付检查见主试验文档；实际世界 RT 仍待实机验收。

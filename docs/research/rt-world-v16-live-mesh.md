# v16：直接 Mesh API 接入游戏内动态模型

v1 独立 B580 回放中，两组完整模型在五种资源/提交路线下的深度和法线逐字节一致，CPU 投影也与实际轮廓对应。该结果允许把已经通过回放的 CreateMesh/DrawInstance 路线接回真实游戏；仍不能据此认定旧实时转换路径异常的根因已经查明。

v16 保留既有世界、天空和 HUD，模型改为每 Draw 读取并重建当前姿态、提交显式 API Mesh 与实例。完整原始 VS/PS 身份、矩阵、骨骼、morph、主相机和特殊通道筛选继续生效。刚体变换仅更新实例；姿态、UV、拓扑、剔除或材质发生变化时使用新 Mesh。UV 不修补，法线暂用面法线，模型使用常量合成材质，原模型贴图尚未接入。

原始 D3D9 Draw 保留一次，在其作用域添加原生 render state 42 的 Ignore 位 3，结束后恢复原值，避免旧 RT 收集器重复消费同一模型。未通过姿态证明的主 HDR 模型也不落回不可靠的旧模型转换。屏外/阴影目标不走该 API 替换。恢复失败会记录并关闭本轮 RT。

CreateMesh 在固定后端内同步复制 CPU 数组，排队命令持有底层缓冲引用。API Mesh 句柄仍保持存活，直至 Present 后 EVENT 查询完成并满足两帧闲置条件，恢复阶段清空已完成资源。最多 512 个缓存项、256 MiB 展开几何、每帧 96 MiB 新几何/128 次提交、8 个未完成查询；上限是实验保护，不是性能验收。退出仅做有界排空，不调用会强制释放游戏设备的 standalone API Shutdown。

启动时在 Host 中清除继承的 DXVK_ENABLE_RAYTRACING，并在 D3D9 初始化和设备注册后重发 RT 关闭等配置。配置 API 返回成功仍只代表请求成功，实际光栅控制、Bloom/PostFX 状态需从本轮图像和运行日志继续核对。Source 线程 CVar、准备线程路径与物理引擎均未改动。

一次 F9 自动执行 600 Present：光栅 30、世界 120、天空 180、Neko 中性灰 240、合并中性灰 300、粗糙 360、金属 420、半透明 480、自发光 540、恢复 600。用户可轻微移动/转头；跨阶段相机或动画不同，禁止直接把颜色差异全部归因于材质。取图帧最多 64 份模型摘要，240/300 各最多 16 MiB 紧凑几何；原输入审计另有独立上限。

日志 revision16；二进制 trace version13 表示新阶段语义，snapshot wire v2 保持不变。分析器同时支持旧 trace，检查逐帧资源计数、GPU 完成进度、合并阶段、原 Draw Ignore 证据、紧凑几何范围/哈希和恢复释放。开发测试覆盖状态恢复故障、API 创建/提交/销毁错误、刚体复用、姿态更新、材质切换、预算和未完成资源不得回收。Windows 原生开发检查与实际 B580 游戏验收分别记录；成功 API 调用、非零深度和测试通过均不等同于画面验收。

本轮通过条件：同一场景世界/天空仍正常；人物随动画连续更新且无旧长条；合成材质至少有可解释的响应；恢复阶段背景恢复且资源归零。原贴图、完整人物/武器、第一人称特殊投影、所有透明通道、原照明、长时间稳定性和生产性能仍未验收。下一步由这轮游戏结果决定修复混合提交边界还是接入原纹理和更完整模型覆盖，避免继续重复收集相同静态输入。

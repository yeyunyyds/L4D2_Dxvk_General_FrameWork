# v10 实机：定位模型变换遗漏，静态扩展尚未通过图像验收

本轮完整完成四段对照，原有墙面、地面和 HUD 保留；新增静态路径每帧成功一次，但没有明确新增的模型表面。实际输入已揭示一个实现缺口：这条模型 Draw 的摆放矩阵存在原 VS 常量中，当前替换路径只使用单位 world，漏掉模型到世界的变换。天空仍回退到 v8，未执行 v9 重建。现有数据足够继续修正，无需原样重采。

输入 `rt-world-20261017-191200-2e07a9d3.zip`，10,160,564 字节，SHA256 `6a9ca130e882ebcc0030d59afc1a249a224d0fb408f3755f1e9f2e99380222ee`，1,045 个成员、解压 103,675,753 字节；CRC 通过，无遗漏。安装的 client/Host 哈希及两端日志身份匹配 v10 构建 `94ce852d30b8689a8c75019d2bc8d06c531a72f7`、`ldb-rt-observer+90c1090847190e71`。三个分析报告独立重析后与上传报告一致；12 张预览逐像素匹配原始颜色、深度及独立八面体法线解码。[结构化复核](../../research/rt-world-191200-review.json) 保存输入哈希、阶段计数、原始状态关联、投影复算及 shader 接口证据。

## 模型：成功提交遗漏了实际摆放矩阵

最后阶段的成功候选是同一 `VertexLitGeneric / 0x80503` 材质，每帧一次。首个样本 ordinal 56071，815 个顶点、736 个三角形，stream0 stride32，无骨骼字段；snapshot world 为单位矩阵。

原顶点位置范围约为 `[-5.26, 0.02, -2.01]` 至 `[5.40, 7.52, 2.01]`，属于模型局部坐标。实际 SM3 VS 的位置路径为：

1. 读取 POSITION0，FLOAT3 的默认 w=1；辅助 POSITION1 乘 c13.x，本次 c13.x=0。
2. 用 c58、c59、c60 分别点乘得到世界 xyz，世界 w=c0.y=1。
3. 用 c8–c11 得到 clip xyzw。

c58–c60 包含约 `(-3089.38, -2532.00, 1280.47)` 的平移及旋转。当前固定功能替换清除原 VS 后只沿用单位 world，没有执行这段模型摆放。按原始 trace 的 view/projection 离线复算：

| 位置处理 | 镜头前顶点 | 视锥内顶点 |
| --- | ---: | ---: |
| 当前局部位置 × snapshot world/view/projection | 0 / 815 | 0 / 815 |
| 应用实际 c58–c60 后再投影 | 815 / 815 | 815 / 815 |

用原 c8–c11 直接执行位置前缀也得到 815 个顶点在视锥内；与 snapshot view×projection 的微小数值差来自保存的矩阵精度。这个结果证明当前实现漏用了位置变换，可以解释该 Draw 为何提交成功却未恢复模型。它仍不证明修正后每个三角形一定可见、无遮挡或已进入 BLAS，也不能由材质地址命名具体道具。

原生仿射 world 用例检查的是“矩阵已给定后是否正确应用/恢复”，没有覆盖“实际 Source shader 的模型摆放是否在别处”。之前把 snapshot world 视为完整模型变换的假设不成立，应补实际输入回归。

修正时必须依据已验证的 shader 位置数据流和当次常量，不能对所有 VertexLitGeneric 无条件套 c58。另一个样本的 snapshot world 已包含同一摆放矩阵，必须避免重复变换。原 VS 的 UV 变换也需一起核对。

## 带骨骼字段的候选中有可成批处理的刚性实例

最后 60 帧的新增静态候选共 960 次：60 次转换成功、720 次被 Layout 拒绝、180 次因 alpha 混合且不写深度被 Pipeline 拒绝。拒绝是门槛结果，没有 setter 或恢复失败。此镜头没有验到透明裁切，未出现 WorldVertexTransition / WorldTwoTextureBlend，不能宣称这些新增路径已实机通过。

完整采到的五份骨骼布局输入（ordinal 56072/56073/56074/56075/56101，分别 4/4/16/24/846 个顶点）全部具有相同模式：

- BLENDWEIGHT 为 SHORT2，原值 `(32767, -1)`；实际 VS 按 `(value+1)/32768` 解码，得到权重 `(1,0,0)`。
- BLENDINDICES 为 D3DCOLOR，四个字节均为 0，实际寻址只选择骨骼 0 的 c58–c60。
- 本次 morph 控制 c13.x=0；五份原 Draw 均不混合、开启深度及深度写入，当前仅因骨骼布局被拒绝。

这五份输入的位置路径可归约为刚性单骨骼变换，有条件成批接入，不必先完成任意人物蒙皮。它们不证明所有 720 次拒绝都具有同样权重，也不证明这些模型跨帧永不动画。后续必须逐 Draw 验证声明、范围、权重/索引、实际 shader 和常量，保留透明及特殊视图限制。

## 天空：需要完整 UV 接口，并处理大坐标精度

96 份场景输入中有 24 份 NekoSky，VS/PS 各只有一个字节码哈希。VS 除 POSITION 外输出 TEXCOORD0–6，保留的 PS 实际声明并使用 TEXCOORD0–4：四次纹理采样加分数坐标插值，不能将额外输出视为无用声明。当前固定功能替换只提供 TEXCOORD0，故 VS 的 `extra_vs_output` 及 PS 输入检查都正确拒绝了该接口。

最后阶段 360 次重建尝试，ready/reconstructed 均为 0，360 次回退原 v8，统一汇总为 `sky_set_not_fully_supported`。因此 240 的天空没有执行新重建；不能据此认定“重建后仍然朝向不对”，也不能只调整一个 UV 翻转或忽略额外声明。

实际天空顶点坐标量级约 58 万。进一步离线检查只移除额外 TEXCOORD 的声明限制、保留所有原始指令及常量，用当前 C++ VM 的 float 运算和反投影函数计算六面：每个面重建齐次 w 相对首顶点的最大变化约 0.0066–0.0140，全部超过现有约 0.0001 的门槛。此检查没有调用 GPU、没有修改生产代码，也没有满足 PS 接口；它揭示补齐多组 UV 后仍需处理的数值问题。

原 VS 的预组合矩阵与 snapshot view×projection 存在浮点舍入差异，大坐标的 clip 运算再经逆矩阵放大误差。不能直接提高容差，否则可能错误改变透视插值。下一步应一起修复所需的五组 UV 和大坐标下的位置/插值保持，并用现有六面输入验证。

## 完整性与退出异常

四阶段各有 24 份输入，共 96 份，payload 1,269,680 字节。52 份几何完整（天空24、模型24、世界4），40 份因顶点范围预算、4 份因索引预算未保存几何；shader 和常量仍保留，所有已保存 payload 的大小/哈希/范围检查通过。这些预算拒绝不是整个结果 ZIP 遗漏，也不能从有界样本计算全地图覆盖率。静态分组无上限遗漏。

Arc B580 完成 GBuffer/Direct/Indirect Ray Query 及 ReSTIR GI 初始化，240 Present 期间未见 IPC fault。控制台已完成采集，随后用户退出：Host 正常确认 Terminate，client 完成清理及输入 Hook 卸载后，仍发生一次执行地址 `0x104b0` 的 `0xc0000005`。栈中两个调用者位于 `necola.dll+0x1447fc/+0x1448de`，当时无活动 Bridge 命令、无命令历史。

因此不能记为“完全干净退出”，也不能凭栈中模块确定责任归属；它是退出链路的独立问题，没有中断本轮采集。此前的 40 个 common device objects 未释放仍存在。诊断跨度约 7.03 秒、含首次 RT 约 1.48 秒停顿及采样/读回，不作为生产性能。

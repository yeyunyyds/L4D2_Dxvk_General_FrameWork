# v6 实机：HUD 恢复，近处白墙仍缺失

本轮确认 HUD 合成入口实际生效，但扩展前后近处白墙都没有产生应有的遮挡。远墙存在不能排除接入覆盖不足：同一份 trace 中有两类尚未支持的 LightmappedGeneric 场景布局。它们是明确的实现缺口，但尚未与白墙的具体 Draw 建立对应，不能提前宣称已定位唯一根因。

输入 `rt-world-20261016-192551-a541fcf1.zip`，8,062,476 字节，SHA256 `0fb0f6e35fd64815b4e1bac52e636bbf6cfb947443841a81b5094d95fe93517d`。43 个成员、解压 105,807,670 字节，CRC 通过、无遗漏。安装的 x86 client/x64 Host 哈希匹配已验证 v6 构建 `4caf3ae55af36bb48da53b367854e30d514f628f`，身份 `ldb-rt-observer+d2c623044c3eae16`。独立重析原始 trace/读回，与上传报告一致；12 张预览均与独立映射结果一致。详见 [结构化复核](../../research/rt-world-192551-review.json)。

## 实际完成的部分

240 Present、83,920 个有效 Draw 快照，正常结束 reason=0；无 Reset、失败、未关联 Draw、viewport 不一致或 pipeline getter 失败。3,630 次世界转换包含 3,150 次原 LightmappedGeneric 和 480 次新增 UnlitGeneric；捕获/应用/恢复的 10,890 个 HRESULT 全部为 S_OK。逻辑 Draw/Present 共有 84,160 个成功回报，其中 120 个 Neko post 原调用被替换，因此不能将这个总数全部称为物理原 Draw。

| 阶段 | 每帧世界转换 | HUD 入口 | 实际图像 |
| --- | --- | --- | --- |
| 1–30 | 无，RT 关闭 | 原光栅 | 近处白墙、左侧白色结构、武器、HUD、天空可见 |
| 31–120 | 15 次 LightmappedGeneric | 未启用 | 远墙/地面可见；近墙、左侧白色结构、武器、HUD、天空缺失 |
| 121–240 | 原 15 次 + 4 次 UnlitGeneric | 每帧一次 | 180/240 的 HUD、文字、弹药、血量可见；近墙仍缺失 |

120 次透明 UI 触发及 post 替换全部 scope_code=9，捕获、应用、draw、恢复均 S_OK；图像同时证明 HUD 恢复，不再仅凭 HRESULT 作验收。新增 Unlit 的调用生效，但其具体物体身份未确定；不能把接受 480 次 Draw 等同于找到了白墙。

武器/手臂仍未接入。HUD 验收只覆盖这次镜头和采样帧，不代表所有菜单、受伤 fade 或 Neko 全套后处理已完成。

## 缺墙属于可见遮挡缺口

120/180/240 的最后转换世界相机完全一致，转换 Draw 中的相机也分别只有一种；本轮固定同一强球灯，不改变光源进行对照。180/240 相较 120 的有效深度遮罩 IoU 为 99.87% / 99.74%，共同命中像素的法线夹角中位数都是 0 度，99.79% / 99.42% 在 5 度内。场景几何轮廓总体稳定，扩展没有补出大块近墙。

颜色图直接显示原白墙位置后的地面和立柱；深度/解码法线也跟随这些远处结构，没有原本近墙的遮挡轮廓。该现象不能由照明偏暗单独解释。左侧白色结构同样缺失，因此不宜先把问题归结为地图中这一面墙损坏；两个缺失对象也未证明具有同一根因。

深度是 RT primary GBuffer 的投影 z/w，控制段 RT 关闭时的该 buffer 不是光栅深度真值；有效命中比例约 76.36%～76.53% 也不是地图覆盖率。当前数据只能确认近墙未参与预期的可见遮挡，不能区分它未提交、被过滤、几何/变换不符或被 RT 剔除。

## 明确发现的两种未支持世界布局

当前白名单只接受 `LightmappedGeneric / 0x480003` 及新增的受限 Unlit。实际上本轮主相机、同尺寸 HDR 目标、无混合/alpha test、写深度、单位 world 的 Lightmapped 绘制还有：

| 格式 | stride | 每帧 Draw | 31–240 总数 | 当前决定 |
| --- | ---: | ---: | ---: | --- |
| `0x480003` | 48 | 15 | 3,150 | 接受 |
| `0x480033` | 64 | 1 | 210 | Material 拒绝 |
| `0x2480033` | 80 | 5 | 1,050 | Material 拒绝 |

后两类共六个材质身份，每帧都在，扩展阶段仍未进入转换。核对实际 declaration 与固定 SDK：两者都有 FLOAT3 position@0、FLOAT3 normal@12、FLOAT2 UV0@24、FLOAT2 UV1@32，前 40 字节与现有世界路径一致；64 字节布局另有 tangent@40、binormal@52；80 字节布局另有 UV2@40、tangent@48、binormal@60。格式中的 `0x30` 是切线空间标志；这两类不是当前拒绝的压缩法线/蒙皮布局。它们都含已记录的 stream2 附加元素，必须按完整声明验证，不能仅凭 stride 放行。

重析 v5 原始 trace，也有同样的 210 次 stride64 和 1,050 次 stride80 未转换候选，因此缺口早于本版 HUD 注入。上一包新增 Unlit 未覆盖这两类，下一步应调整优先级。

远近距离不决定材质和顶点布局。两面墙可以同属 LightmappedGeneric，却因切线、UV 或材质功能不同而只有其中一面被接受。这支持先修复已知覆盖范围，而不是要求用户换图或把缺墙当作正常无光表现。但现有 trace 没有每个 Draw 的光栅屏幕足迹、材质名、顶点/索引内容、CULLMODE 或 RT 实例身份，仍不能断言这六个身份中哪个就是白墙。

## 下一次实现和验收

先接入上述两种精确浮点布局，继续核对 shader/format、完整 declaration、stride、相机、目标及局部状态恢复，保留对未知、压缩和蒙皮路径的拒绝。将原覆盖与新增布局自动对照放在同一次 F9、同一灯光/镜头、一个结果 ZIP 中，并合并有界的材质/Draw 归属记录，用颜色、深度、法线验证新增内容是否恢复了墙体遮挡。若仍未恢复，再以可定位到屏幕区域的几何诊断调查剔除/变换，避免继续盲加 shader。

本轮数据足够安排这一步，不需要立即另换地图或重复同一采集。本文仅记录分析，没有发布新的二进制。完整场景、原地图灯光/PBR、武器/天空、Source 准备任务实际并行和性能仍未验收。Bridge 两端正常退出，未见本轮 IPC fault 或崩溃；退出时 Remix 仍报 40 个 common device objects 未释放，继续保留生命周期问题。

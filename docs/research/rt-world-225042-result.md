## 中断原因已定位到实验上限

最后完整 API 资源统计为338帧：累计提交6,141次，创建4,294个Mesh，复用1,847次、销毁4,126个，剩168项；资源计数逐帧满足 created−destroyed=entries。展开几何剩172,012,800字节，已记录峰值231,523,272字节，GPU完成到337帧，未完成EVENT查询始终最多1个。

二进制trace中，第339帧恰有107次普通模型和21次Neko成功提交，共128次；紧接着JSON记录 `api_model_submit_failed code=8` 并关闭RT。对应 v16 `Scene.draw` 的第一项每帧128次保护：到第129次时，在调用 CreateMesh/DrawInstance 前就返回应用定义的 `ERROR_NOT_ENOUGH_MEMORY`。因此该次错误不能归因于GPU显存耗尽或显卡不支持光追。

trace仍记录到379次成功Present，之后打包时文件尚未完成，没有footer。collector发现非零错误就提前归档，故该ZIP为真实的INCOMPLETE结果；不能由此说游戏在第339帧崩溃或已经干净退出。金属、半透明、自发光、恢复段均未运行，粗糙段在360取图前中断，后端干净清理也未验收。

## v17 合并修复

提高每帧提交上限到512，保留几何字节、缓存和未完成查询上限；新帧第一次模型提交前先轮询并回收已经完成且闲置两帧的旧Mesh，降低瞬时峰值。应用预算不足只遗漏受影响的模型，并记录具体原因、frame/ordinal及统计，继续剩余对照；实际API与状态失败仍停止RT。采集完成与模型预算覆盖分别报告，不能把遗漏写成全覆盖。

同时修正上版漏改的 v15 控制台文案；两组相邻帧数据仍在一次F9内自动采集。结果ZIP采用无损LZMA减少上传大小，原始文件不因压缩被删除。Source线程设置和物理引擎不变。本轮不扩充新的shader家族或改灯光/曝光，先让已实现的六组模型材质与恢复流程完整跑完。

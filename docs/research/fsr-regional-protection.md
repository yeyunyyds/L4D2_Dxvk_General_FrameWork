# FSR 细特效区域保护修正

前版 B580 游戏会话中，3502 个候选只有 174 次生成帧 Present 成功；2466 个候选首先因细特效风险被整帧拒绝。旧预检把任意一个风险像素归约成整帧风险，FSR 因此跳过该帧，之后又因输入不连续重新预热。它把保守保护的影响扩大到了整幅画面。

本轮保留原来的风险检测与计数，并仅在官方 FSR 路径改变处理方式：当前风险标记邻域、当前和前帧细亮形态的滤波邻域保留当前原帧像素，其余区域继续使用官方 SDK 输出与既有遮挡／前景保护。前帧旧位置必须一并处理，否则容易留下旧亮环。普通白色细节也可能被保守识别，这仍然不是材质标签或完整透明层分解。

深度无效、异常前景覆盖和计数异常仍整帧回退，阈值没有放宽。这些不安全输入仍跳过 SDK，随后重新预热。自研后端的整帧细特效保护不变。只有因细特效风险造成的整帧拒绝被区域保护替代，并非承诺所有历史重置都会消失。

后端接口升级到 v2。新 Host 拒绝不具备区域保护的 v1 DLL；混装不会静默放行未经区域保护的输出。请同批覆盖包内五个二进制。

自动截图保留最多 24 组获准生成的候选和 8 组拒绝候选，避免整次上传只有未呈现的诊断图。`capture.quality_accepted` 表示通过质量／历史检查，仍需关联同帧 `generated_present` 和 HRESULT 确认 Present 调用成功。启动脚本同时把 Bridge、DXVK 与 FG 日志写入新的会话目录。

本轮软件 Vulkan 集成回归包括 16 个用例：14 项通过，缺少配套 DXVK 能力与混装 v1 DLL 的两项反向用例按预期回退。实际后备缓冲区检查包含：

- 细环留在当前源帧的位置，前帧旧位置没有亮环残影，同时世界红条处于中间相机位置；预览与双呈现均验证。
- 有风险标记时连续 14 个候选生成成功，除首帧与 Reset 之外没有新增历史预热或整帧拒绝。
- 动态纹理的中间相位及原帧反向对照、遮挡显露、HUD／武器保护、D24/D32、奇数分辨率、失败回退仍通过。
- 自动细环用例保留 9 组成功候选；自动质量回退用例同时保留 6 组成功候选和 3 组拒绝候选，标签与最终质量结果一致。测试没有跑满 24／8 的配额上限。
- 自研后端仍拒绝细环风险，不改变其已验证的回退行为。

47 项 Python 检查通过。详细证据见 [集成验证](../../research/fsr-regional-validation.json) 和 [Windows 包校验](../../research/fsr-regional-package-validation.json)。本轮共接受 143 次官方 FSR 输出，均为 Wine／llvmpipe 测试；不能当作新版 B580 游戏画质或显示节奏验收。前版实机的 174 次成功呈现也不能自动转移为本轮验收。

本轮不以帧率收益为验收目标，也没有把旧日志改判后的潜在通过数当作新输出的画质证据。仍需一次 B580 综合测试观察接受后的真实 SDK 输出。

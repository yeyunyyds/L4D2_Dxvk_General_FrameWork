# GPU 重放 v1：静态模型跑通，五种 RT 路线几何一致

这次获得了实际 B580 上的正面模型重放证据。两个冻结场景中，临时 VB/IB、Present 后释放、持续持有，以及直接 Mesh API 的原 UV/退化 UV 修复两种路径，都显示连贯的人物轮廓。先前游戏内大面积青色与异常长条没有在这些独立、中性材质的重放中重现。此结论限于静态重放，不宣称已修好游戏内模型或全部材质。

## 输入及运行完整性

`rt-replay-20261018-212227-8bdbf31d-01.zip` 为一份完整结果，10,639,280 字节，SHA256 `e18a4714aacdbce43a4c0680da407fd722c383d9d93de496f21864703e5a119d`。207 个唯一成员，展开182,473,773字节，CRC通过，part 1/1，无遗漏清单项。两个重放场景的摘要与已验证的 v15 输入完全一致：240 的21个部件、74,742顶点、109,787三角形，以及420的42个部件、116,812顶点、146,419三角形。

19个独立进程均退出0，各64 Present，共1216 Present；所有被记录的 API/HRESULT 调用成功。程序身份为 `ldb-rt-replay+a8190d7ccb2d9483ba815d5eef1b6ad28d17d998`，GPU为Intel Arc B580 `8086:e20b`，Vulkan1.4.335，固定runtime记录`remix-main+b73eb230`。38张PPM的摘要与review一致，PNG解码像素与PPM相同，34份深度/法线读回大小均完整。[结构化复核](../../research/rt-replay-212227-review.json) 保存逐组调用、哈希与几何对照。

| Neko | 5 | 13,836 | 均逐字节相同 | 0 / 0 |
| 合并人物/武器 | 5 | 14,456 | 均逐字节相同 | 0 / 0 |

五种路线是 `ephemeral`、`retire-present`、`persistent`、`api`、`api-safe-uv`，仅比较中性材质。十组最终颜色均无高亮青色像素，轮廓连贯；法线码没有65535无效端点。所有实例的颜色响应并非逐像素相同，存在采样/曝光等差异，不能将几何一致扩张为完整照明一致。

独立CPU读取相同二进制、world/view/projection并投影全部三角形，模型范围外没有先前的大片异常几何。额外按无抖动像素中心做深度光栅预测，mask IoU约94.67%/94.47%，不是逐像素相等；CPU未复现后端抖动、内部采样和输出重采样，边缘及细小遮挡差异仍存在。三像素范围检查是定位长条的诊断容差，不是几何100%恢复率或完整图像验收标准。

退化 UV 修复分别改变1904/2254个三角形的UV，但两种API路线最终深度和法线完全相同，未显示它是本次几何异常的必要修复。临时资源路线与持久路线同样一致，因此本次没有支持“只延长VB/IB寿命即可修好游戏”的差异证据；游戏内世界/天空混合绘制时的生命周期、缓存交互仍未排除。

## 材质响应与限制

粗糙、金属、棋盘alpha裁切、alpha透明、叠加发光和独立发光均出现相应图像变化。金属整体更暗并有高光，裁切改变轮廓内部与深度，透明产生不同的明暗响应，叠加与发光呈现明显的冷色/暖色发光表现。它们证明了直接API的实际材质响应，尚未证明原游戏材质参数提取、纹理还原或所有混合规则正确。

裁切前景由14,456像素减少至13,052像素；结构化报告进一步记录前景新增/移除与深度单调性，而非仅凭材质创建成功判通过。叠加通道的主深度全为背景1、法线为0，不能按不透明GBuffer判定材质消失。

玻璃最终颜色最大通道仅5/255，深度全为背景，但仍有连贯法线。测试没有高对比背景，不足以判断折射/透射是否正确，玻璃保持未验收，不能把七类材质都写成通过。

## 两项诊断自身问题

Neko“raster”组两张图全黑；合并“raster”组却有接近RT的灰色明暗，且runtime记录GBuffer及光照Ray Query Pass。后者不符合期望的纯光栅基线，两组基线均不能作为有效的光栅/RT对照。源码在创建设备前提交配置，仅记录返回码、没有有效配置读回；API返回0不等同于画面采用了预期选项。确切原因仍需验证，不能仅凭日志判定所有后端路径已经关闭或生效。

发光图有大面积柔光外扩，尽管代码请求关闭bloom/postfx；关闭选项的实际有效性尚未证实。外扩颜色不伴随不透明深度长条，应与几何损坏区分。后续需在已创建设备后重新提交配置，并为关键控制补充可观察的状态/图像验证；修正可与游戏内下一轮合并，不要求用户原样重跑19组。

19组均有 `common device objects were not disposed of` 退出警告。程序记录的 `cleanup=complete` 只说明显式清理调用成功，不代表后端所有对象已释放；本轮没有进程崩溃或采集被中断，退出资源问题继续单列。

## 对实时接入的意义

CPU提交数据、B580上的基本模型RT渲染、直接Mesh入口现在都有相互对应的正面证据；阻塞点已缩小到独立重放与实时游戏之间的差异，包括世界/天空/模型交错绘制、相机/设备状态、原始材质与资源交接。尚未确定唯一根因，也没有性能或Source并行验收。

下一轮应合并推进游戏内直接Mesh模型实例、实时姿态更新和已出现响应的基础材质对照，同时保留世界、天空、HUD，修复诊断配置与基线判定。先以中性材质确认游戏内几何，再在同一次流程切换已支持材质；玻璃加入可观察背景。可以复用当前数据准备实现，无需重复收集这一轮冻结模型。
